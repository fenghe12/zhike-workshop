原100步全零检查点与历史缓存保留。本次分开检查了预处理错误、无效梯度和真实算子兼容限制。

- **DiTalker旧纯色画面的直接原因已确认：** 遮罩未知区域曾填0，原流程填−1。同一100步权重、seed42、CFG1和25步采样，修正此项后恢复人脸。旧潜变量改用FP32解码仍保持失败画面，当前对照不支持将故障归因于VAE精度。
- **新增模块仍未有效训练：** 8/11组全程零梯度，仅30个出口偏置张量、33,028个元素改变。CPU与NPU的相同门控模块对照均复现全零参数导致的零梯度。常规内部初始化、残差出口为零的独立对照得到2、6、71个非零梯度张量；该对照没有替换原100步实验。
- **固定噪声loss：** 修正条件下，50例纯去噪MSE由0.041943734变为0.041973696，略增0.071%。总loss下降主要来自REPA负余弦项。纯MSE、眼部项、REPA与VB现已分项记录，旧mse字段保留其历史组合含义。
- **CogPortrait姿态分支：** 50例、sigma0.5时，平均flow-matching loss由0.047362410降至0.046846089，下降1.09%，48/50例改善。完整骨干重放确认卷积权重与偏置有非零有限梯度及实际更新。代理规划与KTO尚未实现。

当前910B1、Torch2.7.1、torch_npu2.7.1、CANN8.3rc1上复现两项限制：BF16的aclnnReplicationPad1d，以及评估MHA快速路径中BF16 QKV配FP32 bias的aclnnTransformBiasRescaleQkv。前者使用展开与拼接替代并严格匹配CPU输出、输入梯度，后者关闭评估快速路径后执行成功。生产融合注意力的前向与反向通过，不能将零梯度归为缺少注意力算子。
