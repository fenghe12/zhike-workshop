## Actual failure and correction

The NPU attempt failed in CANN initialization before valid measured forwards. A Python multiprocessing Manager failed with `OSError: AF_UNIX path too long`, followed by ACL500001. Updating TMPDIR after Python had cached the original long path was insufficient. The corrected launcher selects a short confirmed persistent directory before Python starts; each runtime also resets `tempfile.tempdir`. A local process-communication reproduction fails with the cached long path and passes after the explicit reset. **The final correction has not been retested on NPU.** This failure does not establish an unsupported model operator.

## Layout and execution

Copy `adaptations/` into the matching Bridge framework's `adaptations/`. `run_remote.sh` and `run_models.py` execute the two models sequentially and invoke the unmodified Bridge adaptation/benchmark checkers. `accuracy_run.py --use-pretrained --max-samples50` loads real full weights once, performs a real demo forward, then two warmups and50 distinct inputs. Use the actual option spelling `--max-samples 50`.

Existing runtime: persistent Python3.11, torch2.7.1+cpu plus torch_npu2.7.1, CANN8.3rc1, diffusers0.35.2, transformers4.53.1, accelerate1.12.0, safetensors0.4.5. The CPU suffix on the torch package does not imply model CPU fallback; explicit NPU selection is required. The uv lockfiles were generated by the resolver. A newly installed isolated environment has not been validated, and the trial reused the existing persistent runtime without installation.

`build_trial_report.py` documents the failed trial; `reproduce_tempdir.py` verifies only the local process-communication correction. Original failed-attempt logs, private cloud state, model files, HDTF data, and the unified report are stored outside the public repository. Existing DiTalker/CogPortrait training records remain separate and unchanged.
